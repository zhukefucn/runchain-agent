# 经理工作台与品牌升级设计

## 目标

将 Phase 1 的经理首页从“固定接待专家团页面”升级为通用多租户 Agent 工作台。默认使用普通单 Agent；接待专家团仅作为多 Agent 能力演示入口。品牌统一替换为润辰科技。

## 方案比较

1. **Codex/ChatGPT 式三栏工作台（采用）**：左侧承载会话和能力入口，中间保持对话主线，右侧按需展示结构化结果。信息层次清晰，也便于 Phase 2 增加业务能力。
2. **固定三栏仪表盘**：结果始终可见，但会压缩对话空间，空结果时浪费面积。
3. **对话内嵌所有结果**：实现简单，但业务表格、文件和执行轨迹会打断对话阅读。

采用方案 1。桌面端维持三栏结构，右栏可折叠；窄屏下左右栏改为抽屉。

## 品牌

- 使用用户提供的润辰科技完整 Logo 替换字母 `R` 与 `RunChain` 组合。
- 登录页副标题保留“AgentScope 多租户智能体”。
- 登录后顶部副标题保留“多租户智能体平台”。
- 浏览器标题改为“润辰科技多租户智能体”。
- 原始 Logo 等比显示，不拉伸、不重绘；使用白底容器兼容其现有白色背景。

## 经理工作台布局

### 左侧功能区

- 新建对话：直接创建普通 Agent 会话。
- 历史会话：展示标题、模式和当前选中状态。
- 能力模式：普通 Agent（默认）与“接待专家团（演示）”。
- 点击专家团入口直接创建专家团会话。
- 空会话发送第一条消息时自动建会话，禁止静默无响应。

### 中间对话区

- 普通 Agent 是默认首页与默认新会话模式。
- 普通 Agent 调用真实模型，并可使用当前经理已授权的 Skill、MCP Tool 与文件空间。
- 专家团会话复用现有真实多 Agent 编排，接站、住宿和餐饮内容仍为 Mock。
- 会话模式由 `agent_id` 标识：`general-assistant` 或 `reception-leader`。
- 未发送消息的空会话可切换模式；第一条消息发送后锁定。切换已锁定会话时创建对应模式的新会话，避免上下文混杂。

### 右侧结果区

- 默认收起，由“结果”按钮手动展开或隐藏。
- 产生结构化业务结果、文件或最终方案时自动展开。
- 包含“业务结果 / 文件 / 执行详情”三个页签。
- 展开状态按会话保存在前端状态中，切换会话互不影响。
- 普通文本回复不强制展开右栏。

## 后端与数据流

1. 创建会话时前端显式提交 `agent_id`。
2. `/chat` 根据已持久化会话的 `agent_id` 服务端分派，客户端不能在发送时覆盖模式。
3. `general-assistant` 使用 AgentScope 单 Agent 运行路径；`reception-leader` 使用现有专家团运行路径。
4. 两种路径共享同一经理身份、授权解析、工作空间隔离、审计与稳定 SSE 协议。
5. 未知或越权 `agent_id` 失败关闭，不回退到另一模式。

## 错误处理

- 自动创建会话失败时在对话区显示明确错误，保留用户输入以便重试。
- 模型、Skill、MCP 失败通过现有稳定错误事件显示，不暴露凭据或内部路径。
- 右栏无对应数据时显示空状态，不显示伪造业务数据。

## 验证

- 单元测试：品牌、模式创建、空会话自动创建、模式锁定、右栏展开状态。
- 集成测试：服务端按 `agent_id` 分派且经理隔离不变。
- 前端构建与类型检查。
- 浏览器演示：普通 Agent 首次对话、专家团新会话、右栏展开/隐藏、两个经理隔离。
- 真实模型冒烟：普通单 Agent 与专家团均可调用 Step 模型。

## 范围边界

- Phase 1 不加入真实爬虫、搜索、OCR、Dify 或真实接待业务。
- 不把专家团结构固化为真实业务组织模型；它只是可替换的能力演示模板。
- 不改变业务管理员与系统管理员的治理职责和隔离边界。
